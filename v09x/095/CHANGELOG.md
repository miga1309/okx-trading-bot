## v095 — 2026-03-21
- Добавлен регулярный мониторинг доступности OKX (public/private/trade/market data).
- Введены состояния CONNECTED / DEGRADED / DISCONNECTED / RECOVERING.
- Новые входы блокируются при деградации/потере связи.
- После восстановления выполняется reconcile живых позиций и проверка биржевых стопов.
- В экспорт анализа добавлены connectivity_log и connectivity_summary.
- Улучшено восстановление entry_time/age sync-позиций из биржевых timestamp.

[v094_3]

- Добавлено глобальное восстановление биржевых стопов для всех открытых позиций: reconcile запускается не только на новых входах, но и на уже живых сделках после рестарта и в рантайме.
- Исправлен критический баг ATR -> TURTLE: если цена стопа уже совпадает с целевой, режим больше не зависает в active=ATR / desired=TURTLE.
- Усилен stop-recovery: при desync, потере algoId, неполном покрытии позиции или битом состоянии бот пытается заново привязать валидный stop-algo, а при необходимости пересобирает его через cancel/place.
- Добавлены события STOP_RECOVERY_START / OK / FAILED / CRITICAL для диагностики проблем сопровождения позиций.
- GOOD-вкладка в Market Scanner больше не схлопывает историю по уникальной паре: таблица строится по trade rows из snapshot (open + closed), поэтому числа больше не расходятся с closed trades.
- GOOD-вкладка переименована по смыслу в «Хорошие сделки», чтобы UI не путал сделки с уникальными парами.
- В snapshot analytics добавлены поля good_positions_open / good_trades_closed / good_trades_total для последующего анализа и экспорта.

[v094_2]

- Исправлен экспорт жизненного цикла позиций: если runtime-state потерян или очищен, открытые позиции восстанавливаются из lifecycle/snapshot и попадают в open_positions_endstate.
- Экспорт closed_trades дополнительно добирает закрытия из lifecycle, если позиция была закрыта, но не успела попасть в runtime closed_trades.
- Summary теперь считает open/closed по фактически экспортированным данным, а не только по текущему runtime snapshot.
